## Why

The player app is a mobile-first Angular SPA that today only ships as a web page. That leaves the three things a field game needs most out of reach: native NFC on iOS (Web NFC is Android-Chrome only), location that keeps streaming when the screen is off or the app is backgrounded, and reliable push on iOS (Web Push does not run inside an iOS WebView, and a home-screen PWA is a second-class citizen). The `nfc-native-and-secure-links`, `live-location-tracking`, `mode-dementors-ble` and `realtime-and-notifications` changes all already assume a "native shell" exists; this change builds it. At the same time the player UI is still raw Bootstrap: the "old-world explorer" design system built in Figma (tokens, components, the Journey · Society · Chronicle · Ledger navigation) has not been ported, so the app does not look or feel like the product that was designed. Doing both at once lets one Angular codebase ship as the web app and as the Android/iOS app with the same layout.

## What Changes

- **Native shell with Capacitor.** Wrap the existing `frontend/projects/player` Angular app with Capacitor 8 (`android/` and `ios/` projects, app id `ro.yetilabs.geogame`, display name "Tower Rush"). The web build stays the source of truth; the native projects are generated and checked in. Android is built and verified in CI-like conditions; iOS is scaffolded and documented (needs a Mac to build).
- **Platform abstraction layer in `shared`.** A `PlatformService` reports web vs. native, and thin bridges (geolocation, background location, push, NFC, haptics, keep-awake, network, secure token storage, deep links, BLE advertise/scan) pick the Capacitor plugin on native and the existing browser API on the web. Existing player screens switch to the bridges instead of calling `navigator.*` directly.
- **Configurable API origin.** Native builds cannot use relative `/api/...` URLs. Add an injectable app config with an `apiBaseUrl` (empty on the web, `https://cercetador.albascout.ro` in native release builds, overridable for dev), an interceptor that prefixes API/media calls, and a websocket URL builder that honours it. Django gains CORS for the Capacitor origins and allows them on the websocket origin validator.
- **FCM push delivery.** The backend already stores `FCM` subscriptions but only sends Web Push. Add an `FcmPushSender` (Firebase Admin, HTTP v1) dispatched by subscription kind, with token-invalid cleanup and settings-driven credentials; the app registers the device token through `@capacitor/push-notifications` on native and keeps Web Push on the web.
- **Native NFC, background location, haptics, keep-awake.** The NFC scan flow gains the native-shell branch promised by `nfc-capture` (iOS and Android through the same token → `/api/nfc/capture/` path). Location streaming keeps pinging at the Session cadence while backgrounded on native, with the OS-required foreground-service notification on Android. Capture confirmations, steals and bonus pop-ups get haptic feedback; the Dementors screen uses native keep-awake.
- **App links.** Serve `/.well-known/assetlinks.json` and `/.well-known/apple-app-site-association` from Django (settings-driven package name, signing fingerprints, Apple team id) so `/nfc/<token>/` and `/join/<code>` open the app when installed; the app routes deep links into the matching screens.
- **Design system port ("old-world explorer").** Port the Figma design system to `shared`: CSS custom-property tokens for the Light and Dark themes (sienna brand, parchment/charcoal surfaces, Playfair Display + Plus Jakarta Sans, spacing/radius/elevation scales, a runtime `--team-color` slot), a self-hosted font setup, an SVG icon set, and Angular components for Button, Chip, Input, Card, StatTile, ProgressMeter, Avatar, TopAppBar and BottomNav. Bootstrap stays for grid/utilities only; Bootstrap component classes are removed from the player app.
- **Player tab layout.** Restructure the player app into the designed shell: a TopAppBar with the current session, and a BottomNav with **Journey** (map, tower detail, scan, trail), **Society** (my team, teams, requests, invites, share), **Chronicle** (session history) and **Ledger** (scores, standings, Dementors status, settings). Safe-area insets, 44px targets, dark mode following the OS, and the existing routes kept as redirects so links and QR codes stay valid.
- **Build and release plumbing.** npm scripts for `cap sync`/`cap open`, an Android debug build recipe, environment files for dev/prod API origins, an app icon + splash from the design system, and a `docs/mobile.md` runbook (Firebase setup, signing, App Links verification, iOS steps).

## Capabilities

### New Capabilities
- `mobile-app-shell`: the Capacitor native shell for the player app — platform detection, native plugin bridges (geolocation incl. background, push, NFC, haptics, keep-awake, network, secure storage, deep links, BLE), configurable API origin, native-origin CORS/websocket allow-list, app-link verification files, and the Android/iOS build pipeline.
- `design-system`: the shared "old-world explorer" design system — light/dark token contract as CSS custom properties, typography, icon set and the reusable Angular UI components consumed by the player app (and available to staff).

### Modified Capabilities
- `player-app`: the player SPA adopts the tabbed Journey/Society/Chronicle/Ledger shell built on the design system, follows OS dark mode and safe areas, and uses the platform bridges (so NFC, location, push and haptics work natively without changing the backend contract).
- `push-notifications`: notifications are delivered through FCM for `FCM`-kind subscriptions (native devices) in addition to Web Push, with invalid-token cleanup.
- `live-location`: on native, location pings continue at the configured cadence while the app is backgrounded, with the OS foreground-service affordance and consent still required.
- `deployment`: the server exposes CORS and websocket origin allow-lists for the native app origins and serves the app-link verification files from settings.

## Impact

- **Frontend**: new `frontend/capacitor.config.ts`, `frontend/android/`, `frontend/ios/`; new `shared/src/lib/platform/*` bridges and `shared/src/lib/ui/*` components and `shared/src/lib/theme/*` tokens; player `app.config.ts`, `app.html`, routes, `styles.scss`, and every screen that calls `navigator.geolocation`, `NDEFReader`, `PushManager` or uses Bootstrap component classes. New npm deps: `@capacitor/{core,cli,android,ios,app,geolocation,push-notifications,haptics,preferences,network,status-bar,splash-screen}`, `@capacitor-community/{keep-awake,background-geolocation,bluetooth-le}`, `@exxili/capacitor-nfc`, `@fontsource-variable/{playfair-display,plus-jakarta-sans}`.
- **Backend**: `organize/push.py` gains `FcmPushSender` + a kind-dispatching sender; new settings `FCM_CREDENTIALS_FILE`/`FCM_PROJECT_ID`, `CORS_ALLOWED_ORIGINS`, `MOBILE_APP_LINKS` (package name, SHA-256 fingerprints, Apple app id); new `/.well-known/` views in `game/views.py`; `django-cors-headers` and `firebase-admin` added to `requirements.txt`; the channels origin validator allows the native origins. No model or migration changes.
- **Ops**: a Firebase project (Android `google-services.json`, iOS APNs key) and an Android signing key are needed before store releases; both are documented, not committed. Production `ALLOWED_HOSTS` already includes `cercetador.albascout.ro`, which becomes the native app's API origin.
- **Staff app**: unchanged behaviour; it may adopt the shared components later but nothing here requires it.
